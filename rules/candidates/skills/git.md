## Git 协作（多会话共用同一份工作副本）

- **署名口径**：**署名以记录层署名与 commit subject 为准，不看 git author**（两台机器的 `git author` 是同一个身份 ⇒ 从 author 分不出是谁做的）。涉及分工归属时看记录层（`send`／`done` 的 `by=`）与提交信息。
- 每完成一个子任务，**立即 commit + push**；备注须准确描述本次修改内容
- **提交前先看 `git diff --cached --stat`**，确认暂存区里只有自己的东西（多会话共用索引，极易夹带别人的改动）
- **提交前手跑 `python .kimi/tools/check_conflict_residue.py`**（查冲突标记残渣 ＋ 索引 CRLF；干净＝退出码 0，发现问题＝非零）。这两条原在 pytest 里，S9′ 退役后降为提交前手跑（迁移清单见 `.kimi/tools/s7_s9_s13_prep_20260929/README.md` §一）。
- **涉及改名/移动时不要用路径限定提交**（`git commit <path>` 会漏掉另一半）；改用 `git add -A <目录>` + 普通 commit，提交后 `git show --stat` 复核
- push 前先 `git pull --rebase`；有冲突先解决再 push
- push 前检查文件，不要出现大文件
- **台账与实现必须一致**：记录里的描述一旦与代码不符（例如"已删某分支"而实际还在），**当场改准并注明更正时间**
- **⚠ 发现「在飞内容」→ 立即报告用户，别自己处置（用户 2026-09-25 新增）**：
  - **什么算在飞内容**：工作区里**不是自己的**未提交改动（`git status --short` 的 `M`／`D`／`R`）与**未跟踪文件**（`??`，含 `git status --untracked-files=all` 展开后的单文件）。**自己的**在飞内容不适用本条的"报告"要求（自己负责按上面几条收口）。
  - **两个触发条件（命中任一即报）**：① **核查不到归属**（文件内容、台账／信箱时间戳、`git log -1 --format=%cI -- <path>`、mtime 都判不出是谁在动）；② **归属明确、但该归属人的最后工作记录已超过 12 小时**（判据＝台账里他最后一条的时间戳／他名下文件 mtime／`git log` 里他最后一次提交，取最新那个）。
  - **报告后不许自行处置**：**不自行 `push`、不自行 `git clean`/`checkout --`/`restore` 丢弃、不自行 `commit` 别人的东西**；**由用户决定 push 或取消**。
  - **报告内容**（照根 `AGENTS.md` §7 结论先行）：路径清单 ＋ `git status` 输出 ＋ mtime ＋ **归属判据**（为什么判给他／为什么判不出）＋ 你的建议（push／取消／留着），让用户一句话就能裁。
  - **为什么**：token 限制会让工作**做到一半就断**，接任者会捡到别人的遗留物；历史上已因此产生过"未跟踪的调试件/证据件"与"别人的在飞改动被误 commit"两类事故。
