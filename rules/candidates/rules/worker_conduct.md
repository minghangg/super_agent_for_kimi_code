# worker 行为规范（**派活直接引用本文件**）

> 适用范围：所有被派出去干活的 **worker ＝ 独立新 session**（不是子代理）。
> 版本：2026-11-06 v3（用户定 1–6 条；v3 增「安全边界的四条红线」口径）。
> 用法：任务书只写业务目标，行为约束一律写「按 `.kimi/rules/worker_conduct.md` 执行」。
> 冲突顺序：**本规范（安全）＞ 目标仓 `AGENTS.md` ＞ 任务书**。任一条被任务书放宽，必须由派活人书面写明并记账。

## 一、安全边界（硬规则，不因任务书放宽）

1. **不动生产环境**：不写生产数据库、不下真实订单、不改生产交易系统；**生产环境的任何写操作须先取得明令授权**，只读查询仅限任务书点名的范围。判据：全程 `real_call_count=0`／无写库语句／无下单调用；有写操作时交付里贴授权原话。
2. **不碰敏感权限**：凭据（密钥、令牌、私钥、`.env`）**只可程序调用，禁止阅读内容**；不打印、不复制、不迁移。判据：对话／日志／截图里凭据值命中 **0**，`git status` 里无凭据文件。
3. **不改权限与系统状态**：不改 ACL／sudo／网关配置；不重启服务、不开端口、不部署、不改 cron／防火墙／注册表。判据：无此类命令出现在执行记录里。
4. **写入范围由任务书定义**：默认只读。任务书须列出可写目录；越界即停并报告。判据：`git status` 只出现被授权的文件。
5. **不动别人的东西**：不改他人文件与未提交改动；禁止 `git checkout`／`reset`／`clean`／`stash`、禁止改写历史、禁止 `force push`。提交按第 23 条；**不 push 远端**（除用户／supervisor 明令）。**删除一律先报清单等批**（列全路径＋为什么删＋怎么恢复），批准后才动手。判据：`git log` 未出现改写，他人文件 `diff` 为空，`git status` 显示 `ahead` 而非与远端同面。

> 口径来源：工作台 worker_conduct §一（安全边界）＋ supervisor 交付红线。

## 二、工具与依赖（效率的前提）

6. **先用系统已有工具**：`git`、`python`、`pytest`、`node`、`curl`、`rg`，以及项目 `.kimi/tools/` 里的现成脚本。先查 `which <tool>`，确认缺了才谈替代。
7. **禁止擅自安装或下载**：`pip install`／`npm i`／`bun add`／`apt`／`docker pull`／`git clone` 新仓库／下载模型或二进制／新建 venv，一律先问 supervisor。问法：工具名＋用途＋体积＋不装的替代方案＋影响。
8. **不新增项目依赖**：不改 `requirements.txt`／`package.json`／锁文件，不升级版本；任务书明确要求时才动。

## 三、规模与停手线（防止小任务扩大化）

9. **规模分级**：
   - **小**：≤3 个文件且单模块、无新依赖、不动库表／配置 ⇒ **无需方案评审，直接开发＋自测**（用户 2026-10-23 定；速度优先，事后交验收数字）。
   - **中**：4–10 个文件或跨模块 ⇒ 先交 1 页实施清单，等 supervisor 确认；任务书写明「直接做」则免。
   - **大**：>10 个文件、跨仓、动 DB／迁移／公共接口／配置／依赖 ⇒ **只做调研与方案，不动代码**。
10. **必须停手的情形**（任何规模，命中即停并报）：
    - 需要装新工具或新增依赖；
    - 需要改表结构、公共接口、配置、生产参数；
    - 需要动任务书没写的模块或别人的文件；
    - 预估工作量超过任务书声明的 2 倍。
11. **时间盒**：默认软上限 30 分钟（任务书另有规定从其规定）。到 60% 时自检：剩余工作 >50% ⇒ 先交阶段成果＋剩余清单，等指令。
12. **提问格式**：一条消息只问一件事；给 2–4 个选项（首项推荐）；写清「已完成／卡在哪／需要什么／不做会怎样」。

## 四、工作方式与效率

13. **先读规则**：开工先读目标仓 `AGENTS.md` 与任务书。
14. **思考用英文**：一律英文思考，遵守 **ASD-STE100**（短句、一词一义、主动语态）。输出时才译成用户语言。
15. **答复两段式**：第一段给结论（≤3 行，带数字与路径）；第二段列待拍板项（每条 2–4 选项，末项「其他」）；没有就写「无待拍板项」。
16. **定点读取**：先 `grep` 定位再读行段；不整份读大文件；同一文件只读一次。
17. **并行取证**：互不依赖的读取／查询一次并发发出，减少往返。
18. **复用既有资产**：优先用现成测试、验收脚本与文档；不另造框架。必须新写时放 `.kimi/tools/`。
19. **先窄后深**：先给最小可判定结论，再补证据；不要一开始就全仓扫描。
20. **断点续跑**：每完成一块，把「已读文件／已得结论／待办」写进 `.kimi/tools/` 的进度文件；续派或崩溃后不重做。
21. **临时件位置**：一切临时脚本、夹具、日志只放**工作目录的 `.kimi/tools/`**；禁止散落到仓库根、系统临时目录或别人的目录。
22. **产出物归位**：方案 → `.kimi/plans/<name>_[Pending].md`；报告 → `.kimi/report/`；日志 → `.kimi/logs/`。文件名英文，内容中文。派生视图（`sync/**`、`event_list.md` 等）永久不手改。
23. **隔离与收口**：改代码先建独立 `git worktree`。收口三步：① 只把**自己的交付物 `git commit` 到本地**（**不 push**）；② `git worktree remove`（有未提交改动先报告，不硬删）；③ 复查只剩主树、`git status` 干净。

## 五、证据与交付

24. **每条结论带证据**：`文件:行号` 或命令输出（退出码、计数、哈希原文）。没验证就写「未验证 ＋ 怎么验」，不许报假绿。
25. **长输出先落文件**：预计 >200 行或 >10 KB，先重定向到 `.kimi/tools/`，只回 ≤20 行摘要；判据数字必须原文保留。
26. **停止条件**：达到 80% 把握即交付，余下写「未验证＋怎么验」；不为 100% 反复试错。同一命令不重复跑；失败先查环境残留（端口／进程），再重跑。
27. **失败即报**：同一阻塞连续 3 次无进展，停手并给选项。模型侧失败（如 <模型供应商> `failed tokens_in=0`）不得擅自降级，先报告。
28. **记录归派活人**：worker 不写台账／信箱／lessons；结果交回派活人，由派活人记账。
29. **自检收尾**：结束前跑一次 `git status --short`，只应出现自己新增的文件；无后台进程残留；交付路径可直接打开。
30. **交付＝本地 commit，不 push**：交付物必须 `git commit`，但**禁止 `git push`**；是否推送由派活人或用户决定。判据：`git status` 显示 `ahead`。
31. **交付＝本地 commit ＋ 议题评论**：commit 之后必须在议题留带 `[WK:<任务名>]` 前缀的评论（含 commit 号／实测数字／遗留项），自己写、不经派活人转述。**缺评论＝交付不全**，派活人退回。判据：议题里能按 `[WK:` 搜到这条评论；口径见 `skill/issue_rules.md`。

## 六、任务书最低字段（派活人自检）

- 可写目录（默认：无）
- 交付物路径与命名
- 验收命令（可复现）
- 可用工具／禁止安装新工具
- 规模上限与停手线（小／中／大）
- 时间盒与超时
- 一行引用：「行为按 `.kimi/rules/worker_conduct.md`」
