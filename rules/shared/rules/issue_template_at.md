# 建单动作模板（AT 备料 → 建单方建单）

> 用途：AT 把用户一句话需求变成「可直接粘贴的 issue 正文」，建单方照本模板建单。
> 本文件管**正文骨架与护栏字段**，不硬编码建单命令（见 §7）。
> 一句话：**AT 备料，建单方建单**。AT 不建单。
> 本文件随包发布（`rules/shared/rules/`），是规则实体。章程按**相对包根**的写法引用它，换机不需要工作台。
> **§1–§6 与 `new_workbench/templates/issue_create.md` 的骨架同源，但不是逐字一致**：随包版本已去私有化（座位称呼统一为「公开侧」，`tools/reedkit/*.sh` → `-m super_agent.issue_cli`）。去掉的只是私有指针，骨架与护栏字段不变。判据：`at_entry.py verify-sync` 只核 lwa 两座之间的 §1–§6 全等；**跨仓一致要单独比**，它不覆盖这一对。

## 1. 标题格式

```
<动词短语>：<现象或目标>（<限定>）
```

- 动词短语在前，不带句号：`AT 长工本体：章程＋-at: 入口＋READY 通知＋建单模板`。
- 限定放括号里：`（自 #60 拆分）`。
- 不写 `[P1]`／`【紧急】` 这类前缀——优先级进 label，不进标题。

## 2. 正文骨架（verbatim，逐段照抄，不增删段落）

```markdown
# <标题>

> <一段起因：从哪来、为什么现在做、谁判归本单。带 issue 号与 cid。>

## 要做的
1. **<条目名>**（`<文件路径:行号>`）：<现状一句> ⇒ <目标一句>。
2. …

## 验收（含反例）
- <正例：命令 ＋ 期望输出＋rc>
- <反例：什么输入 ⇒ 必须 rc≠0 或必须变红>

## 边界
<不许碰的目录／文件；不许做的动作；commit/push 归谁>

## 关联
<#n（说明）／#m（说明）>
```

段落**缺一不可**。少「验收含反例」段＝建单不合格（复核会退回）。

## 3. 护栏字段（建单时逐项确认）

| 字段 | 规则 |
|---|---|
| 标题 | 见 §1；不含 emoji、不含 `[P1]` |
| labels | 缺省 `sev:p2,kind:ops`；带阶段时加 `stage:dev` |
| 正文 | 四段齐全（要做的／验收含反例／边界／关联） |
| 反例 | **至少 1 条**，且必须能红；写不出反例＝没想清楚，不建单 |
| 边界 | 显式写「不碰 X」，并写 commit/push 归谁 |
| 关联 | 上游单号与来源 cid；无关联写「无」 |
| 正文来源 | 文件落 `D:/temp_safkc/`，建单后即可清理；**全文进 issue 正文**，不在本地留派单档 |
| 准入 | 项目必须在准入表里有键（`new_workbench/allowlist.json`；公开侧 `config/gh_projects.json`），无键即 fail-closed 拒绝 |

## 4. 建单动作（三步）

```bash
# 1) 正文落文件（AT 的产物；建单方只读不写）
#    D:/temp_safkc/ISS-<n>_body.md

# 2) 建单：走 supervisor 侧既有建单入口，命令见 §7；本文件不硬编码

# 3) 回读：确认 issue 号、标题、labels、正文段数
python -m super_agent.issue_cli show --project <项目> --issue <n>
```

## 5. 与 AT 的分工

| 动作 | 谁做 |
|---|---|
| 只读调研、备正文 | AT |
| 发 READY（「用户希望在 {项目} 项目建立一个单，已经准备妥当」） | AT（本轨入口见 §7） |
| 建单、贴正文、打 label | 建单方（supervisor） |
| 派 PM 领单 | 建单方（supervisor） |

AT 交付的是**正文文本**；建单方交付的是 **issue**。两者不合并成一步。

## 6. 反例（本模板自身的自检）

- 正文少「验收含反例」段 ⇒ 建单不合格，退回 AT 补。
- 反例写成「正常情况也能过」的句子 ⇒ 不合格（反例必须能变红）。
- labels 缺 `sev:*` ⇒ 不合格（脚本不校验，靠建单人守）。
- 项目未在准入表里 ⇒ 不合格（`at_entry.py` 会 rc=2 拒）。

## 7. 两座差异（登记制；§1–§6 逐字一致，差异只在本表）

| 项 | 工作台侧（`new_workbench/`） | 公开侧（本文件） | 理由 |
|---|---|---|---|
| 建单命令 | supervisor 侧既有入口，命令不定型 | `python -m super_agent.issue_cli create …` | 新轨建单入口尚未定型，不在模板里硬编码 |
| 准入表实体 | `new_workbench/allowlist.json` | `config/gh_projects.json` | 两轨各用自己的准入表 |
| READY 触发入口 | `python new_workbench/tools/at_entry.py ready --project <项目>` | `python -m super_agent.issue_cli`（由 supervisor 执行） | 载体随轨，话术逐字相同 |
| 标题行 | 标注「新工作台座」 | 标注「规则实体」 | 自指必须不同；§1–§6 不受影响 |

**除上表四项，§1–§6 逐字一致。** 新增差异必须先进本表。
