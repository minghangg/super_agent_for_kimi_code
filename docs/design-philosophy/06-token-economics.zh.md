# 06 · Token 经济学

## 执行摘要

一个 agent 团队烧掉的 token，大部分不是花在干活上，而是花在**返工**、**重复解释**和**盯着看**上。本文把这三样从生产里拆出来，然后逐条讲清楚架构上哪些选择能各自消掉一项。

四个判断：

1. **贵的 token 是重复的那一份，不是长的那一份。** 一次返工的代价，超过任何单条 prompt 上可能省下来的钱。
2. **前置投入比返工便宜 —— 但前提是前置投入有边界。** 无上限的澄清不是澄清，是换了副面孔的返工。
3. **上下文烧完的会话，换掉比续上便宜。** 剩下的百分比不是资产，是打了折的负债。
4. **确定性流转应该花零 token。** 一个程序能做的判断，如果交给模型做，那是一个按小时计费的 bug。

以上都不是 prompt 技巧。下面每一个机制都是结构性的：它改变的是**谁**做这一步、或者信息**住在哪**，不是句子怎么写。

## 1. 成本模型：四种 token

把团队花的每一个 token 归进四个桶。

| 种类 | 买到了什么 | 由什么决定 |
|---|---|---|
| **生产** | 交付物本身 —— 读、写、测 | 任务本身 |
| **协调** | 转述、汇总、盯着、问进度 | 交接的次数 |
| **返工** | 同一个交付物的第二次尝试 | 前提错了多少次 |
| **恢复** | 换血、卡死或压缩之后重建上下文 | 有多少上下文只活在会话里 |

总支出是四者之和。设计上的杠杆在于：**只有生产这一项由任务决定**。另外三项是架构的属性，而且三项都能在不降低交付质量的前提下压到接近零。

### 1.1 为什么一次返工能吃掉这么多

看一次失败的交付实际消耗了什么：

```text
worker 第一次尝试        生产
QA 复核                  协调 ＋ 一次完整的独立复跑
QA 写结论                协调
PM 转述结论              协调
worker 第二次尝试        又是生产 —— 还带着第一次尝试的上下文
QA 再复核                协调 ＋ 第二次复跑
```

第二次尝试不是从零开始。它从一个已经装着错误方案、错误文件、错误推理的上下文开始。这份上下文被付了两次钱：造它的时候一次，带进第二次尝试、还得绕着它推理的时候又一次。

所以记账单位不是「每请求多少 token」，而是「**每个被接受并交付的改动多少 token**」。一个在前置上多花一倍、在返工上少一半的架构，赢的幅度很大，而且任务越长，差距拉得越开。

### 1.2 值得记住的那一个数

在我们自己的运行里，大约**三次尝试有一次**能不改就过。这个数就是前置投入的全部理由：如果三次里有两次会被打回，那么一个没做准备的任务，期望成本大约是它生产成本的三倍。把失败率砍一半，比任何单条 prompt 的优化都值钱 —— 因为它一次性消掉了协调、复跑和带过去的上下文三样。

它也给出了前置投入的天花板：**准备工作如果比它防住的返工还贵，那就不是准备，是第二份工作。**

## 2. 逐个机制

每一小节只回答一个问题：**这个机制消掉的是四种 token 里的哪一种，代价是什么。**

### 2.1 角色薄化：PM 只做六件事，转述不加编辑

**消掉：** 协调。

一个既调研、又读实现细节、又跑测试的项目 PM，在干三个人的活，并向团队收三个人的费。更糟的是：它读过的一切都留在它的上下文里，被带进这个项目后续的每一个判断。

纪律刻意收得很窄：PM 领单、判两个开关、原样转述、维持状态机、盯卡死、有界地向上报告。它不调研。调研是一件被派出去的活，有自己的会话，做完就归档。

**转述规则和角色边界同样重要。「转述不加编辑」意味着 QA 的结论原样到达 worker，worker 的结果原样到达 QA。**每一个「我把它说得更委婉一点」的动作，都是一个模型花 token 引入一次失真的地方，然后团队再花 token 发现这次失真。

**代价：** 薄角色会漏掉只有通才才会注意到的信息。这是真的。缓解手段是：记忆是**记录**而不是角色，所以凡写下来的都没丢。

### 2.2 预消化的任务书与有界澄清

**消掉：** 返工，以及返工拖在后面的那串协调。

一个收到「把看板做好看一点」的 worker 会自己发明范围，而发明的范围大约有一半是错的。一个收到「现状事实 + 确切文件 + 验收命令 + 明确不做什么」的 worker 不会。

关键词是**有界**。澄清有停止规则：最多固定几个问题、一次问一个、答案进记录而不是进对话。没有停止规则，澄清就变成无限递归 —— 团队花 token 决定该决定什么。

预消化的任务书还把**便宜模型**的活提前干掉了：一次短调研产出事实，这些事实让强模型把上下文花在真问题上，而不是花在探索上。

**代价：** 前置延迟。写二十分钟任务书，开工就晚二十分钟。只有当预期返工比任务书更长时才划算 —— 而在三分之一的一次过率下，通常都更长。

### 2.3 验收阶梯：为「能失败的最便宜那一层」付费

**消掉：** 恢复，以及一种特定的浪费 —— 跑一个根本不可能抓到该缺陷的昂贵检查。

四级阶梯：

| 层 | 证明了什么 | 成本 |
|---|---|---|
| L0 静态 | 语法、结构、配置解析、产物与源一致 | 秒 |
| L1 单元／契约 | 逻辑、接口、文案 | 数十秒 |
| L2 浏览器／真机 smoke | 真实渲染、交互、console | 分钟，且独占机器 |
| L3 全量＋发版 | 能不能发 | 十分钟，且带生产风险 |

规则是：**从与改动面对应的那一层起步**，只有下层判不了才往上爬。改个 CSS 类名不需要浏览器全套；改存储形状不可能靠手点页面定论。

两条纪律让阶梯真的省钱而不是费钱：

- **独立复跑。** 复核者自己跑命令，而不是相信贴过来的结果。贴过来的是主张，复跑出来的是事实。接受主张，是绿色勾变成装饰品的开始。
- **故意改坏一处。** 在信任一道门禁之前，故意改坏一处，确认它变红。**不会失败的门禁不是门禁**，花在它上面的每个 token 都是浪费。

**代价：** 阶梯增加了流程。它的全部正当性在于：替代方案（每次什么都跑）更贵，而且信息量更低。

### 2.4 35% 规则：换掉烧完的会话，不要续

**消掉：** 在退化上下文里的生产浪费，以及之后要付的恢复成本。

一个一次性短工会话烧掉超过三分之一的窗口之后，继续用它就不便宜了。此后每一轮都在为「重新读一份大半是已完成工作的上下文」付费，而且在一个充满陈旧细节的上下文里做判断，质量更差 —— 这件事会在后面以返工的形式出现。

所以对一次性会话，这道闸是绝对的：**超过阈值就不往里派新活，另起新会话。** 没有覆盖开关，因为新会话很便宜，没有任何理由硬往一个烧完的会话上再压活。

长命角色走另一套更高的刻度 —— 低于某个阈值放行、高于某个阈值要求交接、再高硬拒 —— 因为它们的上下文里装着新会话没法便宜重建的东西：**持续的关系**。

**代价：** 旧会话里剩下的上下文被扔掉了。这正是重点。它本来大半就是开销。

### 2.5 Redirect 与 Reject：错误的前提补不了

**消掉：** 返工 —— 具体说是「建立在错误前提上的第一次尝试」之后的第二、第三次尝试。

两类失败在结论里长得像，但根本不是一回事：

| 类型 | 诊断 | 正确应对 |
|---|---|---|
| **缺陷** | 方向对，实现有 bug 或漏了验收项 | **原地**退回。上下文仍然有效、仍然值钱。 |
| **跑偏** | 需求读错了，或者方案选错了 | **归档会话，另起新的。** 只带过去一句「原方案为什么错」。 |

第二种才是搞错了会很贵的。原地补一个错误前提，意味着为一份装着错误方案的上下文付一次钱，再为「说服模型别这么做」的推理付一次钱，然后在第三次尝试时发现前提还是错的。

可迁移的规则：**如果第二次尝试会带着同一个错误前提，就不要在原地尝试。** 一个带着修正后前提的新会话，比一个被修正过的旧会话便宜。

**代价：** 新会话会丢掉旧会话偶然积累的有用知识。那些知识本该被写进记录；如果没写，这个损失是一个信号 —— 说明记录纪律太弱，而不是这条规则错了。

### 2.6 一次性短工与固定长命会话

**消掉：** 恢复，以及交叉污染的隐性成本。

两种形态，用途不同：

- **一次性短工**：为一个交付物而生，被接受即归档。它看不到第二个任务，所以永远不会把第一个任务的上下文带进第二个任务的判断。
- **固定长命会话**：跨任务保持身份，正是为了不让它积累的判断力每次重建。

这条要防的失效模式是「复用而不轮换」。一个长命会话接下了另一个项目的工作，它不会变得更高效；它会变成一个上下文里混着两样东西、而两半都不干净的会话。症状很隐蔽 —— 回答看上去依然合理 —— 所以这必须是规则，不能是临场判断。

**代价：** 更多会话要命名、绑定、归档。这是记账，而记账是这套系统里最便宜的东西。

### 2.7 消息一行化，细节进记录

**消掉：** 协调，以及长消息引起的重复阅读。

agent 之间的消息应该只带一个结论、一个指针，别的都不带。推理、证据、中间产物 —— 全部进记录，用引用指过去。

理由是算术。一条消息会被收件人读一遍，然后在此后它留在上下文里的每一轮再被读一遍。一条记录只在有人要的时候才被读。把长解释放进消息，等于反复付费；放进记录，等于付一次，而且只在它真的重要时才付。

这也是**本地过程文档不该持久化**的原因。任务书、收口说明、复核报告 —— 这些东西消费一次就变成噪音。它们的持久形态是记录条目：可检索、可寻址、默认不占任何人的上下文。

**代价：** 记录必须真的好。一条指向虚无的一行消息比长消息更糟，因为它逼着对方跑一个来回才发现指针是空的。

### 2.8 无 LLM 的引擎

**消掉：** 协调 —— 在它覆盖的流转上，全部消掉。

那个把条目在状态间移动、通知正确的角色、重试失败的通知、对账关单的引擎，**不做任何语义判断**。它是一个状态机。它的单次流转成本约等于零，而且它不会累、不会漂、不会在第一千次流转时产生幻觉。

这是现有最大的结构性节省，也是最常被留在桌上的一项。一个让模型去判断「这条现在该送 QA 了吗」的团队，是在花钱让模型执行一个 `if` 已经编码好的规则。模型贡献的不是判断力，是延迟和方差。

边界很重要：引擎处理的是**能从记录里判定**的流转。任何需要读需求、形成观点的东西留在模型那边。设计问题从来不是「引擎能不能做这个」，而是「这个判断是一次查表还是一次判断」。

**代价：** 引擎必须被一份干净的记录喂养，而且遇到含糊记录时必须大声失败而不是猜。**会猜的引擎比会猜的模型更糟，因为没人复核它。**

## 3. 诚实地说代价

上面每个机制都有真实的价格。只列收益的文稿是销售材料。

- **延迟。** 准备、门禁、独立复跑，都在第一行生产代码之前增加了墙上时间。对一个本来一次就能过的任务，这是纯开销。
- **刚性。** 35% 的硬阈值会扔掉有时确实有用的上下文。一次性会话的硬规则禁止了偶尔确实高效的复用。
- **记账负担。** 更多会话、更多归档、更多记录。得有人维护，而那个人通常就是同时干所有事的同一个人。
- **转述时的信息损失。** 「转述不加编辑」意味着一条写得糟的结论会以糟的样子到达 worker。规则用失真换了保真，而保真并不总是更仁慈的选择。

这里的主张不是这些机制免费。主张是：**在我们实际观察到的失败率下，它们比替代方案便宜**，而且它们降级得很优雅 —— 如果一个阈值被证明是错的，改它是一行的事，不是一次重新设计。

## 4. 可迁移的判据

向 agent 工作流里的任何一步问五个问题。每一个答「是」，都指向一处具体的节省。

1. **这件事程序能判吗？** 如果这个判断是对记录的一次查表，它属于代码。模型来做，就是为一个恒定答案反复付费。
2. **这个会话的上下文是不是大半关于已完成的工作？** 如果是，换掉它。剩下的窗口不是资源，是下一轮要付费重读的累计开销。
3. **第二次尝试会不会带着同一个错误前提？** 会的话，别在原地试。干净地重开，只把修正带过去。
4. **这条消息会被读不止一次吗？** 会的话，把内容放进记录，只发指针。消息内容在它留在上下文里的每一轮都要付费。
5. **这份信息需要不止一个角色知道吗？** 不需要，它就不该进共享 brief。**共享 brief 是系统里最贵的地产**，因为里面的每一样东西每个人都要读。

再加一条，关于记录本身：

6. **如果这条记录被删掉，团队能从别处重建它吗？** 能，它就是缓存，而缓存不该被当成真源。不能，它就是事实，必须写在换血之后仍然存在的地方。

## 5. 我们不能声称的

这篇文稿从结构论证，不从测量论证。具体说：

- **没有分机制的实测数字。** 我们没有「有 35% 规则」对「没有」的 A/B 测量。这条规则靠成本形状成立，不靠对照实验。
- **三分之一是量级，不是常数。** 它来自我们自己的运行、我们自己的任务构成。换模型、换代码库、换任务形状都会让它移动，而论证只需要它**明显小于一**。
- **token 数不是唯一的成本。** 墙上时间、人的注意力、一次错误发布的风险都是真实的，而它们一个都不在这套账里。一个省了 token 却多花一天延迟的机制，不显然是赢。
- **引擎的零成本是单次流转的，不是单次事故的。** 一个被喂了含糊记录的状态机会卡住，而一次卡住要花一个人的时间。只有在记录纪律成立时，这个零才是真的。

诚实的总结：**这套架构是为了让失败变便宜，不是为了让人一次就做对。** 成功受任务本身限制，失败受设计限制 —— 而后者才是值得工程化的部分。
