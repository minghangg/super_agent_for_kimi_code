# `auth/`：只放指针，永不入值

`auth/` 在本仓是**凭据指针层**，不是凭据仓库。

## 三条硬规则

1. **凭据值放环境变量。** 本目录只记录变量名、以及取值的来源位置。
2. **本目录整个被 `.gitignore` 忽略，且 `tools/privacy_gate.py` 把它列为运行期前缀。**
   目录下任何文件被跟踪，门禁就判 `runtime path tracked (prefix auth/)` 并 rc=1。
   连说明文档也不行——所以说明放在本文件。
3. **不读取、不复制、不打印任何真实值。** 排查问题只引用变量名与指针路径。

## 允许出现的三种内容

| 形态 | 例 | 说明 |
|---|---|---|
| 变量名（右侧空） | `GITHUB_TOKEN=` | 只登记名字 |
| 指针路径 | `SSH_KEY_PATH=<文件系统路径>` | 值是「去哪里找」，不是凭据本身 |

**`auth/` 不在克隆里预置**：它被 `.gitignore` 整目录忽略，连占位文件也不跟踪，所以
`git clone` 之后**没有这个目录**。需要放指针时自己建：

```
mkdir -p auth && printf 'GITHUB_TOKEN=\n' > auth/github.env
```

目录一旦有文件被跟踪，门禁就判 `runtime path tracked (prefix auth/)` 并 rc=1。这不是
限制，是设计：凭据指针不该随仓分发。占位文件在这里没有意义，所以不放。

## 不允许出现

- `KEY=<一段真实值>`（任何长度、任何字符集）；
- 私钥文件本体；
- 带 `Bearer` 的完整请求头；
- 从别的仓复制来的 `.env`。

## 与门禁的关系

`tools/privacy_gate.py` 的 `PATTERNS` 里有 `credential value` 一条，拦的是
「键名 ＋ 赋值 ＋ 长字面量」这个形状。它拦不住「值被贴进 `.md` 正文」这种形态，
所以本目录的第三与不出现清单靠人守，不靠机器。两道门都要。

## 与 `data/` 的区别

`data/` 是运行态（可删、可重建、永不入库）；`auth/` 是凭据指针（可删，但要重建）。
两者都不入 git，理由不同：一个是运行产物，一个是敏感内容。
